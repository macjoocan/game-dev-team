## 팀 구성 (허브-앤-스포크)
```
        [사람 = 최종 권위자]
              │ 승인/지시
        [오케스트레이터 = 메인 세션]
        ┌────┬────┬────┬────┬────┐
       pm  designer dev  qa  artist
```
- 에이전트는 서로 직접 대화하지 않는다. 결과는 오케스트레이터로 돌아오고, 오케스트레이터가 다음 역할로 전달한다.
- 오케스트레이터는 직접 창작/구현하지 않는다. 분배·게이트 확인·사람 보고가 역할.

| 에이전트 | 언제 부르나 |
|---|---|
| `pm` | 태스크 분해·우선순위·이슈 관리 |
| `game-designer` | 기획/밸런스 설계·검토 |
| `developer` | 기능 구현·리팩터링 |
| `qa` | 검증·코드 리뷰·버그 리포트 |
| `artist` | 카드/UI 비주얼 시안·톤 |

## 파이프라인 & 게이트 (사람 승인 없이 다음 단계 금지)
1. **기획/밸런스** (`game-designer`) — 게이트: 근거 없는 수치 0, 미결 명시.
2. **태스크 분해** (`pm`).
3. **구현** (`developer`) — worktree 브랜치, 작은 커밋.
4. **검증** (`qa`) — 통과/조건부/반려 판정.
5. **아트** (`artist`) — 요청서 → 시안 → 승인.

## 코드 컨벤션
- **밸런스 수치(HP·데미지·계수 등)는 코드 로직에 흩뿌리지 말고 한 곳(데이터 객체/테이블)에 모은다.**
- <프로젝트 고유 규칙: 색 변수, 타입 문자열 네이밍 등>
- 기존 동작을 깨지 않는다 — 변경 시 QA가 회귀 확인.
- 규모가 커지면 파일 분리안을 제안하되 사람 승인 후 분리.

## 검증 방법
- <직접 실행/플레이 확인 방법>
- 자동화가 필요하면 헤드리스 스모크 테스트.

## 사람(당신)의 승인 지점

- 변경 머지 승인
- 아트 시안 최종 선택
